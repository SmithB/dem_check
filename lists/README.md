# Crosson low-cloud Landsat list, austral summers 2019-2023

`crosson_landsat_2019_2023.csv` — the images to download and cache for the per-pixel DEM
check over Crosson. `crosson_roi.geojson` — the Crosson polygon the cloud scores were
computed over (EPSG:3031, 82 x 100 km, x -1572496..-1490670, y -636249..-535826).

Generated by `scripts/crosson_landsat_list.py` from the cloudFreeImages FFT cloud
classifier (`notebooks/results/crosson/{summary,inventory}.csv` in
`~/git_repos/cloudFreeImages`, which only exists on the AWS hub). The CSV is the
self-contained product; nothing here needs cloudFreeImages to use it.

## Windows

Jan 1 of 2019-2023, plus and minus two months — five separate Nov 1 .. Mar 1 windows.
180 overpasses cover the Crosson polygon with the sun up in those windows; 46 are
flagged `download`, in 86 scenes.

## Columns

| Column | Meaning |
| --- | --- |
| `summer` | Austral summer, labelled by its January (2019 = Nov 2018 .. Mar 2019) |
| `key` | Overpass key, `<sensor> <date> p<path>` |
| `rows`, `n_scenes`, `ids` | WRS-2 rows and L1 product IDs making up the overpass (`;`-separated) |
| `family` | `descending` (sun az 58-69) or `ascending` (sun az 171-177) |
| `sun_el`, `sun_az` | Degrees, at the polygon centre. From the short Fourier sun formula, 0.05-0.33 deg off the MTL in elevation — recompute from the MTL if that matters |
| `clear_frac` | Fraction of the 480 m classifier cells in the polygon called clear. The cloud score |
| `clear_rift_zone` | Same over the central rift box only |
| `data_frac` | Fraction of the polygon the overpass covers (>= 0.95 for every row here) |
| `catalog_cc` | USGS scene cloud cover, for comparison only — it disagrees badly over ice |
| `tier` | `A` clear_frac >= 0.90, `B` >= 0.70, `C` >= 0.50, `-` below (not for download) |
| `download` | `tier != "-"` |
| `scene_prefixes` | `s3://usgs-landsat` prefix per scene |

Tiers are a starting point, not a verdict. `A` is what the surface-RMS work used for
single-image products; `B` and `C` are still worth having for a per-pixel check, which
screens cloud itself and pools several images per DEM. All seven overpasses picked by
eye for the 2026-11-12 surface-RMS rasters come back as tier A.

## Downloading

Every scene was confirmed present on S3 on 2026-11-15, including LC09 2021-12-23 p007
(rows 113/114), which LandsatLook STAC has dropped — so go by `scene_prefixes` and do
not route this list through a STAC search.

Bands ldcheck wants, all present in each scene directory:

| File | Use |
| --- | --- |
| `<id>_B8.TIF` | Panchromatic, 15 m — the image being checked |
| `<id>_B6.TIF` | SWIR 1.6 um, 30 m — read at 60 m from overviews, NDSI cloud screen |
| `<id>_B9.TIF` | Cirrus, 30 m — read at 60 m from overviews |
| `<id>_MTL.txt` | Rescaling to reflectance, and the true sun angles |

`s3://usgs-landsat` is **requester-pays** and in us-west-2:

    aws s3 cp --request-payer requester <prefix><id>_B8.TIF .
    # GDAL/rasterio: AWS_REQUEST_PAYER=requester, and AWS_NO_SIGN_REQUEST must not be set

**Cut to the ROI, do not cache whole scenes.** The 86 scenes are 36.7 GiB of B8+B6+B9
whole. The Crosson polygon is 82 x 100 km, about a fifth of a scene, so ROI windows are
roughly 3-4 GB for the whole list. Off-hub, requester-pays reads cross regions and
egress is charged, so pulling 36.7 GiB to heimdal costs real money for data that gets
cropped away.
